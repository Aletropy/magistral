# AGENTS.md

## Context
- MVP "Minuta com Personalidade": form (doc type, parties, clauses, persona tone) → LLM → Markdown minuta → preview → downloadable `.docx` / `.pdf`. Product spec lives in `MVP_DOCUMENT.md` (Portuguese).
- Stack: Next.js 16 App Router + React 19 + TypeScript + Tailwind v4 + shadcn/ui (radix, `src/components/ui/`), pnpm, Vitest. Persistence is local SQLite through the built-in `node:sqlite` (Node 26). Three drafting providers, chosen by the `LLM_PROVIDER` env var:
  - `openrouter` is the default. It uses free `:free` models over plain `fetch` with the `OPENROUTER_API_KEY` key, and the model list comes from `OPENROUTER_MODELS`.
  - `gemini` uses `@google/genai`.
  - `anthropic` uses `@anthropic-ai/sdk`.

  Library embeddings are chosen separately by `EMBEDDING_PROVIDER`: `local` (the default, EmbeddingGemma-300m via `@huggingface/transformers` on the CPU, cached in `<data dir>/models`) or `gemini`. The app runs locally only, not on Vercel, because the database needs a persistent filesystem.

## Commands
- `pnpm dev` — dev server. `.env.local` needs `OPENROUTER_API_KEY` (or another provider's key with `LLM_PROVIDER`; see `.env.example`). The database lives at `$MAGISTRAL_DATA_DIR/magistral.db` (default `./data`, gitignored); it is created and migrated on first use. Env files are read at startup, so restart after editing them. The first run prints a setup code for `/configurar`. To try it on a phone, list the machine's LAN address in `MAGISTRAL_DEV_ORIGINS` (e.g. `192.168.1.6`) and open `http://<LAN IP>:3000`; without it the dev server blocks its dev resources and pages never become interactive.
- `pnpm dlx shadcn@latest add <component>` — add a shadcn/ui component.
- `pnpm build` / `pnpm start` — production build and server.
- `pnpm lint` — ESLint (`eslint-config-next`).
- `pnpm typecheck` — `next typegen && tsc --noEmit` (typegen provides globals such as `LayoutProps`).
- `pnpm test` — Vitest, node environment, `src/**/*.test.ts`.
- Single test: `pnpm vitest run src/lib/markdown/parseMarkdown.test.ts -t "<test name>"`.

## Architecture
- Accounts and security (`lib/auth/`, `lib/http/route.ts`, `src/proxy.ts`):
  - Users (`admin`|`member`) and sessions live in SQLite. Passwords are scrypt hashes (`passwords.ts`); the session cookie holds a random token and the DB stores only its SHA-256 (`sessionToken.ts`). Sessions last 12 h without use. Five wrong passwords lock an account for 15 min (`loginThrottle.ts`, per username).
  - First run: with no users, `src/instrumentation.ts` prints a one-time setup code (or `MAGISTRAL_SETUP_TOKEN`); `/configurar` creates the first admin with it and gives them every record from before accounts (`createFirstAdmin`). Admins manage people at `/equipe`; everyone changes their password at `/conta`.
  - Walk-away PIN: an admin sets a 4–8 digit PIN per account at `/equipe` (`users.pin_hash`, scrypt; no PIN = lock off). While it is set, `/equipe`, `/feedback`, `/uso` and `/integracoes` render `UnlockGate` instead of their content, and routes marked `sensitive: true` in `defineRoute` answer 403 until unlocked (`AREA_LOCKED_MESSAGE`). `POST /api/system/unlock` verifies the PIN through the login throttle (`pin:<userId>`, 5 wrong → 15 min) and sets an httpOnly cookie: an HMAC keyed by the raw session token over `magistral-unlock:<pinHash>` (`lib/auth/pin.ts`, cookie names in the edge-safe `pinCookies.ts`), so rotating or removing the PIN re-locks every browser and sign-out deletes the cookie. `src/proxy.ts` drops the cookie on full page loads (reload/back/forward ask for the PIN again); client-side navigations keep it.
  - Every API route is `defineRoute({ access, body, maxBodyBytes, sensitive }, handler)` (or `definePublicRoute` for login/setup). It rejects unknown Host headers (DNS rebinding, `MAGISTRAL_ALLOWED_HOSTS`), cross-site writes (Origin / Sec-Fetch-Site), non-JSON bodies and bodies over the limit, checks the session, the role and — when `sensitive` — the PIN unlock, runs the handler as the user (`runAsUser`, so `withUsageAudit` records `llm_calls.user_id`) and maps errors to pt-BR JSON. Handlers may throw `AppError`. Never export a bare route handler.
  - `src/proxy.ts` does only cheap checks: Host, session-cookie presence (redirects pages to `/entrar?proximo=`, 401 for APIs), the PIN unlock cookie on full page loads, and a per-request CSP nonce (the layout passes it to the theme script). `experimental.proxyClientMaxBodySize` is the largest upload request, since the proxy buffers bodies.
  - Every page calls `requireUser()` or `requireAdmin()` from `lib/auth/dal.ts`, even when the proxy already redirected: the proxy never checks the database.
  - Ownership: minutas, conversations, batch jobs, tasks and notifications have `owner_id`; their repositories take the owner on every read and write, and another user's id reads as missing (404). Personas, clauses and the library are shared; deleting them, library sync/reindex, `/uso` and `/equipe` are admin-only. Tasks carry the owner (`ctx.ownerId`, `taskOwner(ctx)`), and `enqueueTask` caps each user at `MAX_ACTIVE_LLM_TASKS_PER_USER` queued AI tasks (`TaskQuotaError` → 429). A succeeded task's payload is erased.
  - Privacy: OpenRouter requests carry `provider: { data_collection: "deny", zdr: true }` (`PRIVATE_ROUTING`) unless `OPENROUTER_ALLOW_DATA_COLLECTION=true`; a model without a ZDR endpoint yields `NO_PRIVATE_PROVIDER`. `describeDataPrivacy` / `DataPrivacyNotice` tell the admin where texts go. The data dir is created `0700` and the DB `0600`. The unsent minuta draft in localStorage is keyed per user and cleared on sign-out.
  - Prompt blocks: user and document text enters prompts only through `taggedBlock` / `blockGroup` (`lib/prompt/taggedBlock.ts`), which strip closing tags and escape attributes.
- HTTP layer (`lib/http/`): `endpoints.ts` (client-safe route paths), `contracts.ts` (request/response bodies), `status.ts`, `client.ts` (browser fetch helpers), `responses.ts` (`errorResponse`), `route.ts` (`defineRoute`). Domain results (`DraftResult`, `ConsultedSource`) live in `lib/minuta/types.ts`.
- Errors (`lib/errors/`): expected failures extend `AppError` (status + pt-BR message): `MinutaRequestError`, `ChatBusyError`, `LibraryIndexMismatchError`, `TaskInputError`, `TaskQuotaError`. `toPublicError` maps any failure (app, document extraction, LLM via `toErrorResponseInfo`) to status + message; routes, the task worker and the batch worker all use it. Task handlers throw an `AppError` to fail without retrying. `LlmOutputError` is a provider answer that can't be used (refusal, truncated, empty, invalid JSON).
- Live updates: `publishActivity(userId)` (`lib/events/activityEvents.ts`) fires when a user's task starts, progresses or ends, a batch item settles, or a route changes their work. `GET /api/events` streams it as a data-less server-sent event; `ActivityProvider` listens (`live`, `changeCount`), and `useLiveRefresh(refresh, active, fallbackMs)` refreshes followers on each event, polling only while the stream is down.
- Two routes with separate jobs: `POST /api/minuta` validates (zod plus `loadDraftInputs`: persona, clauses, non-empty library) and queues a `minuta.draft` task → answers 202 `{ taskId }`. The task runs `lib/minuta/draftMinuta.ts` (loads the persona, approved clauses and library sources, calls the LLM, runs the output checks, and — only when the caller passes `auditReferences: true`, which just this task does, never the batch worker — checks the draft's norm references against the sources with one extra structured call; a failed audit is logged as `minuta.reference_audit_failed` and the draft ships unchecked) and saves the minuta to the history in `ctx.commit`; `GET /api/minutas/[id]` returns the `MinutaResponseBody`. `draftMinuta` is shared with the batch worker; request problems throw `MinutaRequestError`. `POST /api/export` takes `{ markdown, format }` → returns the file. Downloads never regenerate the minuta. `POST /api/playground` rewrites a sample text with an unsaved persona draft (`lib/playground/`) and never touches the database. Both return `forbiddenTermsFound`: the persona's negative constraints that still appear in the output (`findNegativeConstraintViolations`, which ignores case and accents). `POST /api/style-capture` takes a multipart PDF/DOCX, extracts its text right away (`lib/documents/extractText.ts` via unpdf/mammoth; the file is never stored, the text only lives in the task payload) and queues a `style.capture` task; `/personas/capturar?tarefa=` restores the result. The task asks for a JSON style profile (`lib/style/styleProfileSchema.ts`, via the structured generator below), drops any "verbatim" excerpt not actually found in the text (`verifyExcerpts`), and returns suggestions without writing to the DB; the user saves them through the normal persona routes. Structured JSON answers (style capture, draft suggestions) go through `getStructuredGenerator(operation)`: OpenRouter strict json_schema when `LLM_PROVIDER=openrouter`, Gemini `responseJsonSchema` otherwise, on `gemini-2.5-flash` because free-tier AI Studio keys have zero quota on the Pro models. `parseStructured` turns malformed JSON into `invalid_output`. Persona CRUD is `POST /api/personas` plus `PUT`/`DELETE /api/personas/[id]`; the pages read the repository directly as Server Components (with `await connection()`).
- `lib/db/`:
  - `openDatabase(path)` opens the DB and runs `migrations.ts`, which is versioned by `PRAGMA user_version`. Append migrations and never edit old ones.
  - `client.ts` is the `server-only` `getDb()` singleton.
  - Repositories are pure factories over a `DatabaseSync`, such as `createPersonaRepository(db)`, so tests run them on `openDatabase(":memory:")`. `getPersonaRepository()` is the server-only wrapper.
- One parser, three renderers: `lib/markdown/parseMarkdown.ts` turns Markdown into a `DocumentBlock[]` model. The React preview, `lib/export/renderDocx.ts` and `lib/export/renderPdf.ts` all consume that model, so any Markdown support you add goes into the parser once. Shared typography and page geometry live in `lib/export/layout.ts`.
- The zod schemas (`lib/minuta/schema.ts`, `lib/export/schema.ts`, `lib/personas/schema.ts`) are shared by the client forms and the routes. Field limits are named constants there. `lib/validation/collectFieldErrors.ts` maps zod errors to form fields.
- `lib/llm/`: each provider folder (`anthropic/`, `gemini/`, `openrouter/`) has `config.ts` (model, limits, env var), a `server-only` `client.ts`, `generate.ts` (a multi-turn `ChatGenerator` that turns stop/finish reasons into `LlmOutputError`; single-turn drafting is `asMinutaGenerator(chat)`), and `errors.ts` (SDK errors → HTTP info). `providerRegistry.ts` maps providers to chat generators; `getChatGenerator(operation)` and `getMinutaGenerator(operation)` use it; `generateMinuta.ts` is provider-agnostic and takes the generator as a parameter, so tests inject fakes. `toErrorResponseInfo.ts` maps any failure to an HTTP status and a pt-BR message, and never leaks upstream details. Generators return `{ text, model, usage }`. An `LlmOutputError` raised after the provider answered carries the billed `usage`. `getMinutaGenerator(operation)` wraps the provider in `lib/usage/withUsageAudit.ts`, which logs every call (tokens, latency, estimated cost, status) to the `llm_calls` table without ever failing the generation; `/uso` reports on it. `lib/usage/pricing.ts` holds list prices per model; add the model there whenever you add or change one, or its cost shows as "—". `MinutaPrompt.temperature` comes from the persona. Gemini sends it; Anthropic drops it because Claude Opus 5 rejects sampling parameters with a 400. Every generator takes `{ signal }`: aborting rejects with an abort error (`lib/llm/abort.ts`), recorded as status `canceled`, and OpenRouter never retries it. Adding a provider means a new folder plus an entry in `providers.ts`, `providerRegistry.ts` and `toErrorResponseInfo.ts`.
- Local RAG (`lib/rag/`):
  - Sources live in `library_sources`/`library_chunks`. The FTS5 table `library_chunks_fts` and the sqlite-vec table `library_chunk_vectors` (768-dim, cosine) are kept in sync by triggers, so deleting a source cleans both.
  - `openDatabase` loads sqlite-vec before migrating, and `sqlite-vec` is in `serverExternalPackages`.
  - `chunkLegalText` cuts legislation by article, keeps §§/incisos with their article and records the TÍTULO/CAPÍTULO path. Other text is packed by paragraph with overlap.
  - Embeddings come from `getEmbedder` (`EMBEDDING_PROVIDER`: local EmbeddingGemma pinned to a commit, or `gemini-embedding-2`). With Gemini, pass one `Content` per text: a plain `string[]` yields a single vector; the embed API reports no tokens, so the embedder counts them with `countTokens` for the audit.
  - `selectLibraryContext` puts the whole library in the prompt up to the active provider's budget (`LIBRARY_CONTEXT_BUDGET_CHARS` in `providers.ts`, via `activeLibraryContextBudget()`; chat uses its own 60k). Above that it uses `hybridSearch` (BM25 + vector, Reciprocal Rank Fusion). The task's `signal` reaches the query embedding, so cancelling stops the library step.
  - `/api/minuta` with `useLibrary` adds a `<fontes>` block and grounding rules: cite only what is in the sources, and use `[PREENCHER: fundamento legal]` otherwise.
  - Library routes: `POST /api/library/sources` (multipart upload), `DELETE /api/library/sources/[id]` and `POST /api/library/sync`, which mirrors `MAGISTRAL_LIBRARY_DIR`, default `<data dir>/biblioteca`.
- Clause library (`lib/clauses/`, `/clausulas`, `POST /api/clauses` plus `PUT`/`DELETE /api/clauses/[id]`):
  - `approvedClauseIds` on the minuta request lists pre-approved clauses in the user's drag-and-drop order (`ApprovedClausesField`, @dnd-kit).
  - The prompt carries them as `<clausulas_aprovadas>` with `ordem` attributes, plus rules to preserve their substance.
  - Gemini Flash sometimes moves clauses into conventional order anyway (e.g. foro last). `isApprovedClauseOrderKept` (in `locateClauseSections.ts`) checks the output and the UI warns when the order changed.
- Redline (`lib/diff/wordDiff.ts`, `RedlineViewer`, `RedlinePanel`):
  - It is a word-level diff-match-patch diff, grouped into changes that can each be accepted or rejected. `applyHunkDecisions` rebuilds the text, and the result replaces the minuta Markdown client-side, so preview and export use the reviewed version.
  - Approved clauses are compared one by one, each against the section the model wrote for it (`locateClauseSections` matches headings). Pasted or uploaded originals (`POST /api/documents/extract`) are compared against the whole document.
- History (`lib/minutas/`, `/historico`):
  - Every successful `minuta.draft` task saves the minuta: title from the first H1, the persona name, the request, and the result with the Markdown kept apart. The task result carries its `minutaId`, and its notification links to `/historico/[id]`.
  - Redline reviews persist through `PUT /api/minutas/[id]` (`useReviewPersistence`).
  - `/historico/[id]` is the review page (`SavedMinutaView`).
- Demo data (`lib/demo/`): "Carregar exemplos" on empty `/clausulas` and `/biblioteca` pages calls `POST /api/demo/{clauses,library}`, which is idempotent. The sample norms are explicitly fictitious ("Município de Exemplo"). `public/exemplos/devedores.csv` feeds `/lotes/novo`.
- UI conventions:
  - Pages export `metadata.title`, and the layout template appends "· Magistral". The home page uses the layout default, because a template doesn't apply in its own segment.
  - `app/not-found.tsx` and `app/error.tsx` are in pt-BR; `error.tsx` receives a `retry` prop.
  - Mobile: tables hide secondary columns below `md` (`hidden md:table-cell`) and repeat the key info under the name. The signed-in frame is `components/shell/AppShell.tsx`: a grouped sidebar (`navigation.ts`: Criar / Acervo / Sistema, admin-only links filtered) on `lg`+, a drawer below it, a sticky top bar (bell, theme, `UserMenu`) and a skip link. Single-column grids use `grid-cols-1` so wide children can't widen the page. File pickers use `components/ui/FileInput.tsx`, never a native `<input type="file">`.
  - Texts: say "persona" (not "personalidade") for the managed tone. "Biblioteca" means only the legal library. Avoid jargon (prompt, embeddings, redline, playground). Plurals go through `lib/text/plural.ts`, never "(s)".
- Batch generation (`lib/batch/`, `/lotes`):
  - A job is a minuta request template whose text fields hold `{{coluna}}` placeholders, plus one item per spreadsheet row. CSV/XLSX are parsed in the browser (papaparse, read-excel-file).
  - `src/instrumentation.ts` starts one in-process worker (`getBatchWorker`, a singleton on globalThis) when the Node server boots. It requeues items a crashed process left `running` (failing those with no attempts left), claims items atomically in SQLite, drafts them through `draftMinuta` (without `auditReferences`, so a big batch doesn't double its LLM calls), and retries 429/502/503 with exponential backoff up to `BATCH_MAX_ATTEMPTS`. It takes LLM slots from the same pool as the task worker (`getLlmSlots()`, `lib/queue/slotPool.ts`, 2 at once) and yields while background tasks are due (`shouldYield`), so a user's draft never waits behind a 200-row batch. Deleting a job aborts its items in flight (`cancelJob`).
  - Routes: `POST /api/batch`, `GET`/`DELETE /api/batch/[id]`, `POST /api/batch/[id]/retry` (requeues failed items) and `GET /api/batch/[id]/download?format=docx|pdf` (ZIP built with the regular renderers and fflate).
- OpenRouter (`lib/llm/openrouter/`):
  - `models` is a fallback list. `httpClient` also retries once, with the list rotated, when a free provider fails mid-generation (502/503, or a 200 with `finish_reason: "error"`).
  - Style Capture uses OpenRouter structured outputs (`response_format` json_schema with `require_parameters`) when `LLM_PROVIDER=openrouter`, and Gemini otherwise.
  - Free models are slow (tens of seconds to a few minutes) and allow 50 requests per day without credits. The per-day 429 maps to `DAILY_QUOTA_EXHAUSTED`.
- Embeddings are an `EmbeddingModel` (`id`, `dimensions`, `embed`; see `lib/llm/embeddings.ts`).
  - `library_meta` records which model built the index. `LibraryRepository.addSource` and `hybridSearch` refuse a different model (`LibraryIndexMismatchError`), and `POST /api/library/reindex` (`reindexLibrary`) re-embeds every chunk and resizes the vec0 table.
  - Free (`:free`) and `local/…` models cost $0 in `estimateCostUsd`.
- Background tasks (`lib/tasks/`, `/tarefas`): every slow action is a task, never a long request.
  - Tables `tasks` (status pending|running|succeeded|failed|canceled, JSON payload/result, progress, attempts) and `task_files` (uploaded bytes, deleted when the task succeeds or is cancelled). A handler (`TaskHandler` in `handler.ts`) declares kind, lane, payload/result zod schemas, `run(ctx)`, `describeSuccess`/`describeFailure` (the notification) and optional `onFailed`/`onCanceled` cleanups; register it in `registry.ts` (keyed by `TASK_KINDS`).
  - `createTaskWorker` is slot-based per lane (`llm`: 2, `library`: 1, so reindex/upload never overlap), retries `isRetryableFailure` (never the daily quota) with the shared backoff (`lib/queue/retryPolicy.ts`), and requeues tasks a crashed process left running. `getTaskWorker` is a globalThis singleton started by `src/instrumentation.ts`; restart the dev server after changing a handler.
  - Side effects that must not happen after a cancel go through `ctx.commit(write)`, which runs them in the transaction that marks the task succeeded (`withTransaction` nests with savepoints). Cancel = `POST /api/tasks/[id]/cancel` → `worker.cancel` aborts the running `AbortController`.
  - Routes answer 202 `{ taskId }` via `enqueueTask(handler, { title, payload, files })`. Client side, `useBackgroundTask(resultSchema, initialTask, { queryParam })` starts and follows a task and keeps its id in the URL (`?tarefa=`; the minuta workspace uses `?rascunho=` for suggestions); server pages read it (`readTaskParam`) and pass the initial task. `FollowedTaskStatus`/`TaskStatusCard` show progress, cancel and retry.
  - Notifications (`lib/notifications/`): one row per finished task or batch (`describeFinishedJob`, once per job via `batch_jobs.notified_at`). `ActivityProvider` (in the layout) polls `GET /api/activity?since=` (15 s idle; 2 s while work runs only when the `/api/events` stream is down), toasts new notifications with sonner (skipped for the page already open) and raises opt-in OS notifications when the tab is hidden; `NotificationBell` in the nav lists running work and recent notifications. Finished tasks and notifications are purged after `TASK_RETENTION_DAYS`.
- Pages use `components/layout/Page.tsx` (title, description, actions, width), `EmptyState` for empty lists, `Pagination` + `readPageParam` for paged lists (`/historico?q=&persona=&pagina=`), and `app/loading.tsx` shows `PageSkeleton`. Because of that loading boundary pages stream, so `redirect()`/`notFound()` inside a page answer 200 with a client-side redirect/not-found view (the proxy still sends real 307s for signed-out requests).
- `/` is the dashboard (the `AssistantHero` composer, recent minutas and conversations, live `ActiveWorkCard`, shared counts, privacy notice); it forwards old `/?tarefa=` and `/?rascunho=` links to the workspace.
- Minuta workspace and base document (`/minutas/nova`, `NEW_MINUTA_PATH`):
  - `MinutaStudio` (prop `layout`) holds one `MinutaFormValues` for two pages: the guided wizard at `/minutas/nova` (`MinutaWizard`, shown full screen by `FocusShell` — `FOCUS_PAGES` in `AppShell`) and the advanced form at `/minutas/nova/completo` (`MinutaForm`, sections via `MinutaStepFields`, `MinutaSummary` beside them; the batch creator reuses `MinutaForm`). Both pages load through `loadStudioState`.
  - The wizard asks one thing per screen. `WIZARD_STEPS` (`lib/minuta/wizardSteps.ts`) is ordered tipo → inicio → partes → condicoes → clausulas → persona → fundamentacao → revisao; each step has a schema, tips (a collapsed "Dicas") and `isRelevant(context)`: `clausulas` only when approved clauses apply to the type, `fundamentacao` only when the library has documents (`relevantSteps`). The wizard tracks the step by id because the list changes with the type.
  - `lib/minuta/documentTypePresets.ts` gives each type its card summary, default party roles and essential questions. The conditions step's answers (`WizardConditions`) become the request's `clauses` text through `buildClausesFromConditions` ("- Label: answer" lines plus free text), so the API and batch templates are unchanged; `applyPresetRoles` relabels untouched parties when the type changes; an AI suggestion or the advanced form's text comes back as the "other conditions" box (`conditionsFromClauses`). The stored draft keeps the answers (`conditions`, null for older drafts). The unsent form is saved in localStorage per user (`lib/minuta/storedDraft.ts`) and offered back. When the draft task succeeds, the page navigates to `/historico/[id]`; `?tarefa=` of a finished draft redirects there (`loadDraftTaskState`).
  - `/historico/[id]` is the review page (`SavedMinutaView`): document or redline tabs, and a side panel with downloads, warnings (forbidden terms, clause order) and consulted sources.
  - `minutaRequestFieldsSchema` is the unrefined object (steps `.pick` from it); `minutaRequestSchema` adds the "outro" rule. `baseDocument` (`{ name, text }`, ≤ 60k chars) defaults to null so old history rows and batch templates still parse; the prompt wraps it in `<documento_base>` with its own rules, and `sanitizeTagContent` strips closing tags from any wrapped text.
  - `POST /api/minuta/sugestoes` queues `minuta.extract`: the model reads a base document or an Advogado IA conversation into `draftExtractionSchema` (form fields, a persona id, review notes); `toSuggestedDraft` drops unknown clause/persona ids and clips to the form limits; `applySuggestion` fills the form. `/minutas/nova?rascunho=<taskId>` opens the wizard on the review step with it applied.
- Advogado IA (`lib/chat/`, `/assistente`):
  - Tables `chat_conversations` (optional `minuta_id`, `use_library`) and `chat_conversation_messages` (assistant replies are `pending` while a `chat.reply` task writes them; one pending reply per conversation, `ChatBusyError` → 409).
  - `chatReplyTask` runs the agent loop (`lib/assistant/runAgent.ts`) with `buildChatSystemPrompt`: role, answer and tool rules, the app guide (`appGuide.ts`; update it when features change), the user's personas/clauses/library titles (`loadAppData`), the library mode (`on`/`off`/`empty`) and the saved minuta when the conversation is about one. `normalizeChatHistory` drops unfinished replies, merges turns, trims the oldest and replays past tool steps as text (plus a synthetic "[Aviso automático do Magistral]" user turn for each decided action); `rewritePastCitations` spells out old `[Fn]` because each reply has its own sources.
  - Tool calling: `lib/llm/tools/types.ts` (`ToolDefinition`, `ToolCall`, `AgentMessage`, `ToolChatGenerator`), one `generateWithTools.ts` per provider (OpenRouter adds `require_parameters` to the private routing when tools are sent; Gemini/Anthropic replay the model's own content via `providerContent` within a reply so thought signatures survive), `TOOL_GENERATOR_FACTORIES` in `providerRegistry.ts`, and `getToolChatGenerator(operation)` (audited).
  - `runAgent`: at most `MAX_AGENT_STEPS` model calls; each call's arguments are validated with the tool's zod schema (errors go back to the model); read results are cut to `TOOL_RESULT_MAX_CHARS` (or the tool's `maxOutputChars`) and wrapped in `<resultado_ferramenta>`; the first action call stops the loop with an `awaiting_confirmation` step; out of steps it asks once more for an answer with `STEP_LIMIT_NOTE`. Library excerpts are numbered across the reply by `createCitationRegistry`.
  - Tools (`lib/assistant/tools/`, one factory per file taking repositories, wired in the server-only `getAssistantTools.ts`): read tools `buscar_biblioteca` (only offered when the conversation uses a non-empty library), `listar_personas`, `listar_clausulas`, `buscar_historico`, `ler_minuta` (owner-scoped), `ver_tarefas`, `abrir_pagina` (link card) and `preparar_minuta` (stores a finished `minuta.extract` task via `TaskRepository.createFinished`, opened with `?rascunho=`); actions `gerar_minuta`, `editar_minuta` (exact-excerpt replacements, redline card), `criar_clausula`, `ajustar_persona`. An action is `defineActionTool({ propose, execute })`: `propose` validates and builds the card (plus a `state`, e.g. a `fingerprint` of the text so `execute` refuses with 409 when it changed meanwhile). The worker import in `enqueueDraft` is dynamic to avoid a cycle through the task registry.
  - Steps live in `chat_tool_steps` (`ChatMessage.steps`; `input` never leaves the server; cards are `toolCardSchema`: link, fields or redline). `POST /api/chat/conversations/[id]/steps/[stepId]` `{ decision: "confirm"|"reject" }` → `decideStep`: owner check, `claimStep` (so it runs once), `execute`, `recordStepOutcome`, then `addContinuation` + `startReply` for the follow-up (202 `{ taskId }`). A new user message dismisses waiting actions (`STEP_DISMISSED_OUTPUT`). `ToolSteps` renders step rows and the confirm/reject cards.
  - Panel on every page (`components/assistant/`): `AssistantProvider` (inside `AppShell`, around both the normal frame and `FocusShell`) keeps it open or closed, toggles it on Ctrl/⌘+K, and remembers the conversation it continues in localStorage per user (`lib/assistant/panelStorage.ts`, cleared on sign-out). `AssistantPanel` is a non-modal right-hand drawer: `PanelStart` (first question, ideas, recent conversations) or `PanelConversation` (loads the conversation, `ChatThread compact`, "Tela cheia" link). `AssistantButton` sits in the top bar ("Pedir ajuda" in `FocusShell`) and hides on `/assistente` pages. The dashboard opens with `AssistantHero`, whose conversation continues in the panel. `useStartConversation` is shared by the hero, the panel and `/assistente`.
  - Page context: pages render `<AssistantContext kind id detail />` (minuta review, persona and clause editors, batch, and the wizard with its step and parties); otherwise the page title is used (`pageTitleContext`). Messages from the panel carry `context` (`pageContextSchema`, `lib/assistant/pageContext.ts`), which `startReply` puts in the `chat.reply` payload; the task resolves it with owner checks (`describePageContext`) into the prompt's "Onde o usuário está" `<contexto_da_pagina>` block.
  - Routes: `GET`/`POST /api/chat/conversations`, `GET`/`PATCH`/`DELETE /api/chat/conversations/[id]`, `POST …/messages`, `POST …/messages/[messageId]/retry`. "Criar minuta a partir desta conversa" posts `{ source: "conversation" }` to `/api/minuta/sugestoes`; `/historico/[id]` starts a conversation about the minuta.
  - Migration `reconcileLegacyChat` moves conversations from an early prototype's `chat_threads`/`chat_messages` and relabels `assistant` usage as `chat`.
- Integrations (`lib/integrations/`, `/integracoes`, admin only): the `integrations` table holds one row per outside service; `client_information`, `tokens` and `code_verifier` are sealed with AES-256-GCM (`lib/security/secretBox.ts`, key derived from `MAGISTRAL_SECRET_KEY`; without a 32+ char key `getSecretBox` throws a 503 `AppError` and the page explains it; a changed key marks the record `unreadable` and asks to reconnect).
  - Jurisprudências.ai (`lib/integrations/jurisprudencias/`): the office's single account, reached through its MCP server (`https://jurisprudencias.ai/mcp`, streamable HTTP) with `@modelcontextprotocol/sdk`. `oauthProvider.ts` implements the SDK's `OAuthClientProvider` (public client, dynamic registration, PKCE, scope `mcp`; a registration made for another redirect URL is discarded). `POST …/connect` returns the authorization URL, `GET …/callback` (admin session, state checked in constant time) exchanges the code and always redirects to `/integracoes?conexao=`, `DELETE` disconnects. The redirect URL is `${MAGISTRAL_PUBLIC_URL}/api/integrations/jurisprudencias/callback` (the request origin in development). `client.ts` `callJurisprudencias(tool, args)` opens a client per call, lets the SDK refresh tokens, maps 401 to "reconnect", limit messages to `JurisprudenciasLimitError`, and audits every call as operation `jurisprudencia` / provider `jurisprudencias` (model `jurisprudencias/<tool>`); `/integracoes` shows today's calls since midnight in Brasília (`countCallsSince`, status ok only).
  - Assistant tools `pesquisar_jurisprudencia`, `consultar_decisao`, `listar_tribunais` (`lib/assistant/tools/jurisprudencia.ts`) are offered only while `isJurisprudenciasConnected()`; decisions are numbered `[J1]…` by the citation registry (JSON lists are annotated per decision, other answers get one reference per call), every result carries the "Fonte: Jurisprudências.ai" credit note, and `/historico/[id]` shows a "Pesquisar jurisprudência" button while connected. Each conversation carries a per-conversation `use_jurisprudencia` toggle, which reaches the prompt as `"on" | "off" | "unavailable"`; the answer's prose is never regex-edited — decisions stay in "Fontes consultadas" with the credit line, and the rules only prefer natural references over scattered mid-sentence markers. Limits (free 5 searches/10 lookups a day, subscriber 500/10,000) live in `config.ts`; the service's result format is not documented, so the tools pass its text through.
- `withUsageAudit` is generic over any call returning `{ model, usage }`; wrap every new LLM call with it and give it an `LlmOperation`.
- Theme (`lib/theme/theme.ts`, `ThemeToggle` in the nav):
  - Light/dark is a `dark` class on `<html>`, set by `THEME_INIT_SCRIPT` in `<head>` before first paint. It uses the choice saved in `localStorage["magistral-theme"]`, or else follows the OS setting.
  - Colors come from the tokens in `globals.css` (`:root` and `.dark`, including the `warning` tokens used by `WarningCallout`). Don't hardcode palette classes like `bg-amber-50` in app components.
  - The document previews stay white on purpose, like paper.
- pdfmake is in `serverExternalPackages` and uses the PDF standard font Times. Times only encodes Windows-1252, so `splitByFont` (`lib/export/pdfFonts.ts`) draws every other character (≥, →, ✓, Greek) with DejaVu Sans from the `dejavu-fonts-ttf` package, loaded into pdfmake's in-memory file system on the first render and embedded only when used. Its access policies deny URLs and every local path except the standard font names.

## Deployment (test release)
- `docker-compose.yml` runs the image from `Dockerfile` (Next.js `output: "standalone"`, non-root, `/app/data` and `/app/backups` named volumes, `HEALTHCHECK` on `GET /api/health`) behind Caddy (`deploy/Caddyfile`: automatic HTTPS for `MAGISTRAL_DOMAIN`, `flush_interval -1` for `/api/events`). Settings come from `.env.production` (`.env.production.example`); guide in `docs/deploy.md`. Build the image on the target architecture.
- The standalone tracer can't see files loaded from computed paths; `RUNTIME_FILES` in `next.config.ts` adds them (the sqlite-vec platform package and its pnpm link, onnxruntime-node's Linux binaries where Transformers.js requires it, the hoisted onnxruntime-common, the DejaVu fonts). When adding a native dependency, run the standalone server (`node .next/standalone/server.js` after copying `.next/static` and `public`) and exercise it.
- `src/instrumentation.ts` validates settings with `checkEnvironment` (`lib/config/`): a production server exits on errors (provider key, `MAGISTRAL_PUBLIC_URL`, `MAGISTRAL_SECRET_KEY` ≥ 32 chars); development only warns. The public URL's host is allowed automatically (`allowedHostsFromEnv`).
- Daily maintenance (`runDailyMaintenance` in `lib/tasks/getTaskWorker.ts`) purges old records and, with `MAGISTRAL_BACKUP_DIR`, writes `magistral-YYYY-MM-DD.db` with `VACUUM INTO`, keeping 7 (`lib/db/backup.ts`).
- Server logs are JSON lines via `logEvent` (`lib/log.ts`). Release info (`lib/config/release.ts`): version from `package.json` and `MAGISTRAL_COMMIT`, inlined at build; `MAGISTRAL_RELEASE_CHANNEL=teste` shows the "Versão de teste" badge.
- Testers report problems with the top-bar feedback button (`feedback` table, `POST /api/feedback`); admins read them at `/feedback`. `/privacidade` is public (proxy `PUBLIC_PATHS`) and linked from sign-in, setup and the user menu.

## Git workflow
- `main` is the default branch. Don't commit changes directly to it.
- Start every change on a new branch named `<type>/<short-kebab-description>`, e.g. `feat/pdf-page-numbers`, `fix/docx-line-stretch`, `chore/bump-deps`. Types: `feat`, `fix`, `chore`, `refactor`, `docs`, `test`.
- Commit messages follow Conventional Commits with the same types: `feat: add page numbers to PDF export`, `fix(export): keep signature lines in lists`.
- Merge back into `main` only when the user asks.

## Constraints
- One responsibility per module/component; no god classes, no magic numbers/values (name constants).
- Never commit stub or half-implemented features; ship only working paths plus basic LLM-API error handling.
- Never add AI-attribution comments, commit trailers (e.g. `Co-Authored-By`), or notes about files being staged/sent to git.
- Keep API keys server-side only; never expose them to the client bundle. Anything importing a provider's `client.ts` or `getMinutaGenerator.ts` must stay server-side.
- Server-only modules (`lib/db/client.ts`, `get*Repository.ts`) must never be imported by client components; client components get plain props or call the API routes.
- `.gitignore` excludes `AGENTS.md`, `CLAUDE.md`, and `MVP_DOCUMENT.md` from git. Force-add them if the intent is to share edits.
